Build a complete, polished, working website for a fictional South African barber shop called “CROWN & BLADE”.

This is a Junior Full-Stack Developer practical assessment. The finished product must be publicly deployable and feel like a professional website created for a real client.

Implement the website and its functionality. Do not stop at a plan or a visual prototype. Work through the requirements below and test the result.

PROJECT PRIORITIES

1. A distinctive, professional design.
2. A complete booking experience with bookings saved in a database.
3. Working Google Calendar and Apple Calendar-compatible appointment export.
4. Excellent mobile usability.
5. Complete content and working interactions throughout.

Use Lovable Cloud for the backend and database if available. If enabling it requires my approval, ask for it. Do not silently replace database persistence with localStorage or display a successful booking when nothing was saved.

Write finished, natural content. Do not use lorem ipsum, fabricated customer reviews, fake awards, or unsupported claims about years in business.

This is a fictional assessment business. Use appropriate fictional business information without impersonating an existing shop. State discreetly in the footer that it is a fictional business created for a practical assessment.

AVAILABILITY AND PERSISTENCE

Use database-backed services, barbers, and appointments.

Generate available appointment times from opening hours, the selected service duration, the selected barber, and existing bookings.

Enforce these rules on the backend as well as the frontend:
- No dates or times in the past.
- No Sunday bookings.
- No appointments outside opening hours.
- The full service duration must fit before closing.
- No overlapping appointments for the same barber, including overlaps between services of different durations.
- Two customers attempting to reserve the same slot must not both succeed.
- If a slot becomes unavailable, explain what happened and let the customer select another.

Use an atomic server-side booking operation or database constraint to prevent booking races.

Store only necessary customer information. Public visitors must not be able to read other customers’ names, emails, phone numbers, notes, or contact messages. Availability responses should expose available times, not private booking records.

Keep secrets out of frontend code. Apply suitable database access policies.

On the successful booking confirmation screen, provide:

1. Add to Google Calendar.
2. Download for Apple Calendar (.ics).

Both must use the confirmed, saved booking details:
- CROWN & BLADE.
- Selected service.
- Selected barber.
- Selected appointment date.
- Correct start time.
- End time calculated from the service duration.
- Location information.
- Booking reference and useful appointment details.

Implement Google Calendar using a correctly encoded event-creation link.

Generate a valid .ics file for Apple Calendar and other compatible calendar applications. Include a unique UID, DTSTAMP, DTSTART, DTEND, SUMMARY, DESCRIPTION, and LOCATION. Properly escape text and use valid calendar formatting.

Handle Africa/Johannesburg correctly. An appointment selected for 15:00 South African time must represent that same instant in both calendar exports. Do not accidentally shift it through incorrect UTC conversion.

Do not hard-code one appointment for every customer.

Do not require Google OAuth or a calendar API key merely to create an event link or download an .ics file.

Explain accurately that the customer must complete the calendar action in their calendar app. Opening a link or downloading a file does not prove an event was saved to their calendar.
