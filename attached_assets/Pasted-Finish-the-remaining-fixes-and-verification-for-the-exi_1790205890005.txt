1. FIX THE APPLE CALENDAR .ICS EXPORT

A downloaded appointment file currently contains:

DTSTART;TZID=Africa/Johannesburg:20260925T150000
DTEND;TZID=Africa/Johannesburg:20260925T154500

However, it contains no VTIMEZONE component.

Fix this standards-compliance problem. Prefer exporting DTSTART and DTEND as UTC timestamps ending in Z, with no TZID parameter on those properties.

For example:
- 25 September 2026, 15:00 SAST must become:
  DTSTART:20260925T130000Z
- A 45-minute appointment must end at:
  DTEND:20260925T134500Z

These are test examples, not values to hard-code.

- Date and time conversion uses Africa/Johannesburg explicitly, regardless of the customer’s device timezone.
- Duration determines the correct end time.

- DTSTAMP is a valid UTC timestamp.
- SUMMARY, DESCRIPTION, and LOCATION carry the correct appointment information.
- Description includes service, barber, and booking reference.
- Text escaping handles backslashes, commas, semicolons, and newlines correctly.
- Lines use CRLF endings.
- Long lines are folded correctly according to RFC 5545’s 75-octet recommendation.
- The file uses a suitable .ics filename and text/calendar MIME type.
